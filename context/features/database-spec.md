# Database Setup - Prisma + Neon PostgreSQL

## Overview

Set up Prisma ORM against the Property Pulse Neon **development** branch, create the full schema from `@context/project-overview.md` section 7 as the initial migration, and add a Prisma client singleton. This is the foundation for auth phase 1, which no longer needs to set up the database.

`DATABASE_URL` is already set in `.env` (Neon development branch).

## Steps

### 1. Install Packages (ask first — new dependencies)

```bash
npm install @prisma/client @prisma/adapter-neon
npm install -D prisma dotenv
```

Use Context7 to confirm the current Prisma version's package names and setup before installing.

### 2. Initialize Prisma

```bash
npx prisma init
```

Then adjust what it generates:

- `prisma/schema.prisma` - schema (step 3)
- `prisma.config.ts` - CLI config (step 4)
- Do **not** let `prisma init` overwrite `.env` — the existing `DATABASE_URL` must stay

### 3. Write the Schema

Copy the enums and models from `project-overview.md` section 7:

- Enums: `Role`, `PropertyType`, `PropertyStatus`, `InquiryStatus`
- Auth.js adapter models: `User`, `Account`, `Session`, `VerificationToken`
- App models: `Property`, `PropertyImage`, `Favorite`, `Inquiry`

Update the header for Prisma 7 (the overview shows the older style):

```prisma
generator client {
  provider = "prisma-client"
  output   = "../src/generated/prisma"
}

datasource db {
  provider = "postgresql"
}
```

- `prisma-client` replaces `prisma-client-js`, and `output` is required
- The connection URL moves out of the schema and into `prisma.config.ts`
- Keep the model definitions exactly as in the overview (Decimal rent fields, compound `Favorite` key, indexes)

### 4. Configure `prisma.config.ts`

```ts
import "dotenv/config";
import { defineConfig, env } from "prisma/config";

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: {
    path: "prisma/migrations",
  },
  datasource: {
    url: env("DIRECT_URL"),
  },
});
```

- The CLI (migrations) should use Neon's **direct** (non-pooled) connection. Add `DIRECT_URL` to `.env` with the development branch's direct connection string (same as `DATABASE_URL` without `-pooler` in the hostname)
- The app at runtime uses the pooled `DATABASE_URL` (step 6)

### 5. Run the Initial Migration

```bash
npx prisma migrate dev --name initial_schema
```

- Confirm first that `DIRECT_URL` points at the **development** branch, not production
- Never use `prisma db push`
- This generates the client into `src/generated/prisma`

### 6. Prisma Client Singleton

`src/lib/db.ts`:

```ts
import { PrismaNeon } from "@prisma/adapter-neon";
import { PrismaClient } from "@/generated/prisma/client";

const globalForPrisma = globalThis as unknown as { prisma?: PrismaClient };

function createPrismaClient() {
  const adapter = new PrismaNeon({ connectionString: process.env.DATABASE_URL! });
  return new PrismaClient({ adapter });
}

export const db = globalForPrisma.prisma ?? createPrismaClient();

if (process.env.NODE_ENV !== "production") globalForPrisma.prisma = db;
```

- Import path ends in `/client`
- The singleton prevents too many connections during Next.js hot reload
- Server-only: never import from client components or edge code (`auth.config.ts`, `proxy.ts`)

### 7. Project Housekeeping

- Add `src/generated/prisma` to `.gitignore` (generated code is never committed or edited)
- Add a `postinstall` script: `"postinstall": "prisma generate"` so builds regenerate the client
- `.env.example` with variable names only. Note: `.gitignore` currently ignores `.env*`, so add `!.env.example` if it should be committed (ask first)

## Files to Create / Update

1. `prisma/schema.prisma`
2. `prisma/migrations/<timestamp>_initial_schema/` (generated by `migrate dev`)
3. `prisma.config.ts`
4. `src/lib/db.ts`
5. `package.json` - dependencies, `postinstall`
6. `.gitignore` - `src/generated/prisma`
7. `.env` - add `DIRECT_URL` (not committed)

## Environment Variables

```
DATABASE_URL=   # Neon development branch, pooled (-pooler) — app runtime
DIRECT_URL=     # Neon development branch, direct — Prisma CLI / migrations
```

## Testing

1. `npx prisma migrate status` - "Database schema is up to date"
2. `npx prisma studio` (or the Neon Console tables view on the development branch) - all 8 tables and 4 enums exist
3. Production branch is untouched (no tables)
4. `npm run build` passes with `src/lib/db.ts` in place
5. `npm run lint` passes

## Out of Scope

- NextAuth setup (auth phase 1)
- Seed data and demo users (auth phase 2)
- Any queries or server actions using the database
- Switching the homepage's featured properties to database queries
